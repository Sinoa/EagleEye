# ONNX/Unity互換性チェック

対象: $ARGUMENTS

## 手順

### 1. Unity ONNX制約の読み込み

`docs/ARCHITECTURE.md` の §8「Unity ONNX対応」から制約を確認する。

### 2. 対象コードの特定

`$ARGUMENTS` からチェック対象を特定する:
- ファイルパス、ディレクトリ、またはコミット範囲
- 引数なしの場合: `src/MLCoreModule/` と `src/MLModelCodec/` を対象にする

### 3. チェック観点

対象コードを読み込み、以下の観点でチェックする:

**カスタム演算子**:
- TorchSharpのカスタムオペレーターやユーザー定義演算子を使用していないか
- ONNX標準オペレーターセットに含まれない演算がないか

**Attention演算の分解**:
- Attention演算が以下の基本演算子に分解可能か:
  - `MatMul` — 行列積
  - `Transpose` — 転置
  - `Mul` — スケーリング
  - `Softmax` — 確率化
  - `Reshape` — 形状変更
  - `Add` — 加算（バイアス、残差接続）
- `torch.nn.functional.scaled_dot_product_attention` 等の高レベルAPIを直接使用していないか

**活性化関数**:
- SiLU（Swish）を使用しているか
- ReLU、GELU等の他の活性化関数が混入していないか（SiLUに統一すべき）

**正規化**:
- LayerNormを使用しているか
- BatchNormが使用されていないか（バッチサイズ1で動作しない、学習/推論で挙動が異なる）
- InstanceNorm、GroupNorm等が混入していないか

**動的軸**:
- バッチ次元とシーケンス長が動的軸として正しく定義されているか
- 重み行列がシーケンス長に依存していないか（`[dim, dim]` 形状であるべき）
- ハードコードされたシーケンス長がないか

**テンソル操作**:
- `view` / `reshape` の形状引数に `-1` を適切に使用しているか
- 動的な形状推論がONNXエクスポート時に正しくトレースされるか

### 4. 結果報告

- **互換**: Unity ONNXランタイムで問題なく動作する箇所
- **違反**: 互換性がない箇所（具体的な代替実装の提案を含む）
- **要検証**: エクスポートして実際に動作確認が必要な箇所
