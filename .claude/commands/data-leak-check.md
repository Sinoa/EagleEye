# データリーク防止レビュー

対象: $ARGUMENTS

## 手順

### 1. チェックリストの読み込み

`docs/ARCHITECTURE.md` の §10「データパイプライン」にあるデータリーク防止チェックリストを参照基準とする:

| 情報 | 含めてOK |
|------|---------|
| 自分の手牌 | OK |
| 他家の手牌 | NG |
| 全員の捨て牌 | OK |
| 全員の副露 | OK |
| 全員の点数 | OK |
| リーチ状態 | OK |
| 山牌の残り枚数 | OK |
| 山牌の中身 | NG |
| 裏ドラ | NG |

### 2. 対象コードの特定

`$ARGUMENTS` からレビュー対象を特定する:
- ファイルパス、ディレクトリ、またはコミット範囲
- 引数なしの場合: DataPipeline関連のコード全体を対象にする

### 3. 特徴量の列挙

対象コード内で使用されている特徴量をすべて列挙する:
- GameStateのどのプロパティにアクセスしているかをコードから追跡
- PlayerStateのプロパティアクセスを特に注視（`Hand`, `Discards`, `Melds`, `Score`, `IsReach` 等）
- 視点変換（相対位置への変換）が正しく行われているか確認

### 4. データリーク判定

各特徴量について以下を判定:

**許可される情報**:
- `players[selfIndex].Hand` — 自分の手牌のみ
- `players[*].Discards` — 全員の捨て牌
- `players[*].Melds` — 全員の副露
- `players[*].Score` — 全員の点数
- `players[*].IsReach` / `ReachTurnNumber` — リーチ状態
- `RemainingTileCount` — 山牌残り枚数
- `DoraIndicators` — ドラ表示牌

**禁止される情報**:
- `players[otherIndex].Hand` — 他家の手牌（最重要チェック項目）
- 山牌の具体的な並び順や内容
- 王牌の内容
- 裏ドラ表示牌
- 和了結果からの逆算情報（結果を知った上での特徴量構築）

### 5. 視点変換の検証

- アクターの視点から相対位置に変換されているか
- 自分の手牌以外のプレイヤーの手牌にアクセスしていないか
- ループで全プレイヤーの手牌を処理している箇所がないか（捨て牌・副露・点数は全員OK、手牌は自分のみ）

### 6. 結果報告

- **安全**: データリークなしと判定された箇所
- **違反**: データリークの疑いがある箇所（コード位置、アクセスしているプロパティ、修正案を含む）
- **要注意**: 直接的な違反ではないが、将来的にリークにつながる可能性がある設計パターン
