# アーキテクチャ準拠レビュー

対象: $ARGUMENTS

## 手順

### 1. 対象の特定

`$ARGUMENTS` からレビュー対象を特定する:
- ファイルパス、ディレクトリ、またはコミット範囲
- 引数なしの場合: `git diff --name-only` でステージング済み・未コミットの変更ファイルを取得

### 2. ARCHITECTURE.md の関連セクション読み込み

`docs/ARCHITECTURE.md` を読み込み、変更内容に関連するセクションを特定する。

主要なチェック対象セクション:
- **1. モデル全体アーキテクチャ** — 入力次元、エンコーダー構成
- **4. Attention・Transformer設計** — 位置エンコーディング、集約手法
- **5. 副露エンコーディング** — 18次元構成
- **6. 場況特徴量** — 約78〜90次元構成
- **7. 出力設計・アクション空間** — BCE統一、マスク処理
- **8. Unity ONNX対応** — 演算子制約、動的軸
- **10. データパイプライン** — 前処理/学習の分離、JSONL形式
- **12. バリアント設計** — 4人/3人麻雀の共通化・分離原則

### 3. 準拠チェック

対象コードを読み込み、以下の観点でレビューする:

**入力設計**:
- 手牌入力: 牌埋め込み(4) + インスタンスID埋め込み(2) + ツモフラグ(1) = 7次元になっているか
- 捨て牌: RoPE位置エンコーディングが適用されているか
- 副露: 18次元構成（牌埋め込み4 + 種別5 + 鳴き元4 + 順序4 + 巡目1）に従っているか
- 場況: 区分線形変換の点数正規化パラメータが設定ファイルで外部化されているか

**エンコーダー構成**:
- 手牌: Self-Attention（位置エンコーディングなし）→ CLS出力
- 捨て牌: Self-Attention + RoPE → CLS出力
- 副露: MeldEncoder(Linear→SiLU) → 平均プーリング
- 場況: MLP(2層) → 場況特徴ベクトル

**出力設計**:
- BCEで統一されているか
- アクションマスクが `logits + (-1e9f) * (1 - mask)` パターンか

**バリアント設計の分離原則**:
- 共通化すべきもの（TransformerBlock, RoPE等）が共通コードに配置されているか
- 分離すべきもの（牌埋め込み、アクション空間等）がバリアント固有コードに配置されているか

**Unity ONNX互換性**:
- カスタム演算子を使用していないか
- 活性化関数がSiLU/Swishか
- 正規化がLayerNormか
- 動的軸が正しく定義されているか

### 4. レビュー結果の報告

以下の形式で報告する:

- **準拠**: 設計方針に合致している箇所
- **逸脱**: 設計方針と異なる箇所（具体的な修正提案を含む）
- **未定義**: ARCHITECTURE.mdに規定がない新しい設計判断（ドキュメント更新の要否を提案）
